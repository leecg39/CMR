# CMP 오토 리서치 결과

실행일: 2026-10-01. 발송 허용 판단의 SQL 왕복을 줄이는 **3회 실험을 완료**했습니다. 변경 대상은 `packages/policy-engine/index.ts`의 조회 부분입니다.

## 결과

- 허용 마케팅 판단 1건의 SQL 호출: **12 → 6회, 50% 감소**.
- BEGIN·고객사 설정·직렬화 잠금·COMMIT의 고정 4회까지 합치면 **16 → 10회, 37.5% 감소**입니다.
- 3개 실험 모두 유지, 폐기 0개, 실험 크래시 0개입니다.
- 각 실험의 최초 측정과 확인 측정에서 고정 의미 검증 20개가 통과했습니다. 각 단계의 기존 자동 테스트 **63개**, TypeScript 검사와 빌드도 통과했습니다.
- 최종 실제 HTTP·DB PoC **10개**가 통과했고 자신의 임시 DB·역할을 정리했습니다.

| 단계 | 가설 | SQL/판단 | 5회 p95의 중앙값 | 별도 확인 측정 | 결정 |
|---|---|---:|---:|---:|---|
| 기준 | 기존 순차 조회 | 12 | 8.120 ms | 7.418 ms | 기준 |
| 1 · c473e67 | 회원·연락처·템플릿·발신자 조회 결합 | 9 | 6.681 ms | 6.953 ms | 유지 |
| 2 · ab3424f | 목적·수신 동의·마케팅 이용 동의 조회 결합 | 7 | 6.400 ms | 6.521 ms | 유지 |
| 3 · e5d21cc | 고객사 활성 상태·월 사용량 조회 결합 | 6 | 5.816 ms | 6.231 ms | 유지 |

초기 기준 8.120 ms와 최종 확인 6.231 ms를 비교하면 약 23.3% 감소했습니다. 기준을 다시 측정했을 때 7.418 ms와 7.065 ms도 나왔으므로 시간 차이에는 환경 편차가 포함됩니다. 유지의 주 지표는 반복 실행에서도 동일한 **SQL 호출 수**입니다.

본 프로젝트의 서버는 Node.js 22.23.1을 사용하므로, 동일한 동결 평가를 Node 22에서 수정 전·후에 추가 실행했습니다. SQL **12 → 6회**, p95 중앙값 **7.474 → 5.951 ms**였고 20개 의미 검증이 통과했습니다. 본 프로젝트에서도 기존 테스트 **63개와 빌드를 다시 통과**했습니다. API와 워커를 새 코드로 재시작했고 `/v1/health`의 PostgreSQL·데모 모드와 홈페이지 HTTP 200을 확인했습니다. 평가에서 만든 `cmp_research_*` DB·역할은 0개입니다.

## 고정 평가와 유지 기준

평가 코드와 기존 테스트를 실험 전에 SHA-256으로 고정했습니다. 각 실험은 구현만 먼저 커밋한 뒤 측정했고, 종료 시 평가·테스트 파일의 해시가 모두 일치했습니다.

- 매 측정은 새 PostgreSQL DB와 NOSUPERUSER/NOBYPASSRLS 비소유자 역할을 사용합니다.
- 워밍업 20건 뒤, 100건·동시성 5를 5회 실행합니다. 한 측정의 표본은 500건입니다.
- 직전 최선보다 SQL 호출 수가 줄어야 합니다.
- p95 중앙값은 최초 기준의 120%인 **9.744 ms 이하**여야 합니다. 측정기는 조건 위반 시 실패 종료합니다.
- 고정 의미 검증, 수정하지 않은 `npm test`와 `npm run build`가 통과해야 합니다.

의미 검증은 허용·판단 증빙 저장, 동의 누락, 미검증 증빙, 한도, 제한 회원, 연락처 검증·채널, 템플릿 승인, 공급자 준비·080 동기화, 목적 검수·목적 없음, 고객사 비활성, 야간, 철회·수신거부·리비전, 없는/다른 고객사의 회원·연락처·템플릿, 권한 거부를 포함합니다. 기존 회귀 테스트에는 동시 철회 뒤 새 허용 차단과 예약 취소도 포함됩니다.

## 변경과 한계

조회들을 합쳤으며 판단 조건·사유 순서·판단 원장 기록은 유지했습니다. JOIN에는 고객사 키가 포함되고 기존 FORCE RLS와 고객사별 트랜잭션 잠금이 적용됩니다. 캐시를 추가하거나 현재 동의의 재확인을 생략하지 않았습니다.

3회 실험은 작업공간의 Node.js v25.4.0, 실제 서버 환경 추가 확인은 Node.js 22.23.1에서 실행했습니다. macOS arm64, PostgreSQL 17.11의 합성 데이터와 로컬 연결입니다. 서로 다른 Node 버전 간 지연은 비교하지 않았습니다. 큰 고객사 데이터, 원격 DB·네트워크, 운영 트래픽의 성능은 이 결과로 보장하지 않습니다. UI를 바꾸지 않았으며 이번 실험에서 브라우저 QA를 다시 수행하지 않았습니다. 앞선 브라우저 결과는 [QA 보고서](../../qa/2026-10-01/report.md)에 있습니다.

문자·080 실연동과 실제 파일럿은 사용자 요청대로 보류했습니다. 실제 메시지를 발송하지 않았습니다.

## 재실행

프로젝트 루트에서 실행합니다. 로컬 PostgreSQL 관리자 연결이 필요하며 평가 DB·역할은 실행별로 생성·삭제됩니다.
