# 제한 출시 관문

기준일: 2026-10-01. **현재 판정: 출시 보류.** 로컬 합성 PoC와 모의 연동의 통과는 실제 고객·발송·운영 환경의 검증을 대체하지 않는다.

사용자가 문자·080 실연동과 파일럿 검증을 후속으로 미루도록 요청했다. 로컬 구현·PoC·최신 웹 검증은 완료했으며, 아래 실제 운영 관문은 후속 일정에서 진행한다.

## 단계별 증거와 상태

| 관문 | 현재 상태 | 출시를 위해 필요한 실제 증거 |
|---|---|---|
| 설치·서버 기록·고객사 격리 | 로컬 검증 통과 | [PoC](POC.md)와 동일한 검증을 운영과 동등한 환경에서 실행한 기록 |
| 동의 코어·웹 CMP | 로컬 합성 흐름 통과 | 고객 사이트별 등록 태그 목록, 미선택·거절·부분·전체·철회 후 요청 측정, 우회 태그 점검 |
| 문자·080 실연동 | 미실행. 현재 SOLAPI 설정 없음, 실발송 비활성 | 등록 발신번호와 080 계약 확인, 허가된 수신번호의 실제 수신·거부 왕복, 공급자 결과와 원장 대조 |
| 스캐너 격리 | 로컬 Linux/Docker 검증 통과 | 운영 환경과 고객 사이트에서 비루트 sandbox·프록시 경유·사설 주소/직접 egress 거부·자원 제한 재검증 |
| 운영 인증·비밀 관리 | 로컬 데모 환경 | HTTPS, 데모 모드 해제, 관리자 MFA 등록, 비밀 관리, 키 폐기·접근 권한 증거 |
| 백업·복구·장애 대응 | 합성 전체 DB 암호화 백업·복원과 삭제 이력 재내보내기 보존 통과. 운영 복원 미실행 | 운영 백업 매체·키·객체 저장소 복원, 삭제 이력 재적용, 장애 중 광고 보류·철회 접수·통지 담당자 대응 훈련 |
| 고객별 처리 구조 | 미확정 | 문구·목적·보유기간 검토 결과, SaaS·고객사·공급자 역할과 운영 책임 확인 |
| 과금·정산 | 내부 사용량·한도만 구현 | 결제 사업자 계약·청구·정산·해지 검증 |
| 파일럿 2–3곳 | 미실행 | 고객별 설치부터 문자 철회·증빙 내보내기까지 결과, 우회 경로와 통제 범위, 담당자 승인 |

## 문자·080 실검증 절차

1. 한 SOLAPI 계정을 한 고객사에 연결한다. 키는 서버 환경에 넣고 등록 발신번호·080 계약·허가된 시험 수신번호를 확인한다. 공급자를 검증 완료로 표시하기 전에 담당자와 시험 범위를 기록한다.
2. 승인된 문구로 목적·채널·번호 범위의 동의를 새로 수집한다. 공급자 접수 ID와 실제 수신 결과를 원장의 판단·템플릿 버전·발송 시각과 대조한다.
3. 미래 예약 뒤 080 수신거부를 실행한다. 공급자 거부 발생 시각, 동기화 시각, 내부 철회·예약 취소·outbox 반영 시각을 기록한다. 철회 반영 뒤 새 광고 승인과 미실행 예약의 발송이 없어야 한다.
4. 처리결과 통지와 공급자 결과를 확인한다. 접수 전·후 타임아웃과 응답 유실에서 자동 중복 전송이 없는지 확인한다. 접수 후 취소 가능 범위와 거부 반영 지연은 관측한 결과로 공개한다.
5. 시험 증빙을 개인정보 최소화 상태로 내보낸다. 시험 중 실패·불명·누락이 발생하면 광고 경로를 중지하고 [PoC 대체 설계와 재검증 조건](POC.md)을 적용한다.

합성 데이터의 발신번호·080 번호를 실제 공급자 시험에 사용하지 않는다. 실제 시험은 준비된 계정과 승인된 번호가 있어야 실행할 수 있다.

## 제한 출시와 중단

파일럿 고객마다 사이트·담당자·허용 채널·규모·실발송 한도·운영 시간을 정하고 위 관문의 증거를 확인한다. 도입 첫 흐름은 **사이트 설치 → 선택별 태그 통제 → 회원 문자 동의 → 발송 전 판단 → 예약 → 철회 → 다음 승인 차단 → 증빙 내보내기**로 실행한다.

교차 고객사 접근, 철회 후 새 승인, 원장 유실, 모르는 접수의 중복 전송, 오래된 080 상태에서 발송, 복구 뒤 삭제 대상 재활성화 중 하나라도 발견되면 영향을 받는 광고 경로를 보류한다. 철회·거부 접수와 증빙 접근은 유지하고 원인을 고친 뒤 해당 시나리오와 전체 고객사 격리를 재검증한다.

출시 판정에는 실행일, 환경·소스 버전, 시험 담당자, 결과·실패 사례, 증거 파일, 재검증 결과, 고객사 승인 기록이 필요하다. 준비 상태 체크박스나 환경변수만으로 실연동 성공과 출시 승인을 인정하지 않는다.
