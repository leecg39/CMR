# 구현 범위와 출시 관문

## 구성

React/Vite 관리자 콘솔, Fastify API, 별도 작업 워커, PostgreSQL 관계형 저장소로 구성했습니다. `USERCENTRICS`의 기존 코드와 문서를 읽고 비교했으며 그 저장소는 수정하지 않았습니다. 이 프로젝트는 독립 구현입니다.

```text
apps/console        React 관리자 화면
apps/api            인증·동의·정책·메시지·웹 공개 API
apps/worker         통지·발송·접수 조정·거부 전파
apps/scanner        격리 Chromium 검사 및 공인 IP만 허용하는 프록시
packages/database   SQL 스키마·마이그레이션·트랜잭션
packages/consent-domain  범위·권한·암호화·원장
packages/policy-engine   버전 있는 판단·예약 등록
packages/web-sdk     배너·설정·태그 로딩·GTM 템플릿
packages/connectors  모의 공급자 및 SOLAPI 어댑터
packages/evidence    증빙·파기·삭제 이력 복구
packages/test-fixtures   합성 시나리오
```

## 중요한 처리 방식

### 순서와 범위

테넌트별 PostgreSQL advisory transaction lock으로 철회와 새로운 발송 승인에 순서를 부여합니다. 잠금 안에서 원장·현재 상태·거부·예약 취소·전파 작업을 함께 기록합니다. 네트워크 전송은 이 트랜잭션 밖에서 실행하고, 승인·접수 시각을 따로 남깁니다. 이미 승인되어 전송 중인 호출은 이후 철회로 취소를 보장하지 않습니다.

개인정보 마케팅 이용과 채널 수신 동의가 모두 필요합니다. 웹 선택의 거절은 문자 동의를 변경하거나 문자 예약을 취소하지 않습니다. 다른 사업자의 동의·거부도 자동 확대하지 않습니다. 전화번호 변경은 이전 번호를 비활성화하고 새 번호에 새로운 동의를 요구합니다.

이관 데이터는 증빙 미확인 상태입니다. 통지와 이관은 동의일을 갱신하지 않습니다. 저장소에 접근하지 못하면 새로운 광고 판단이나 발송을 진행하지 않습니다.

### 저장소와 인증

앱은 소유자·슈퍼유저·BYPASSRLS 역할을 거부합니다. 테넌트 데이터는 RLS와 복합 외래키로 보호합니다. 로그인 계정·세션·소속·키와 테넌트 디렉터리는 인증을 위해 서버 내부에서 조회하며, HTTP 응답과 변경에는 인증된 범위를 적용합니다.

비밀번호는 scrypt, 세션과 서버 키는 해시, 연락처는 AES-256-GCM, 번호 조회는 테넌트별 HMAC을 사용합니다. TOTP 재사용을 차단하고 상태 변경에는 Origin 검사를 적용합니다. 운영 배포에서는 HTTPS와 MFA 등록을 완료한 후 `REQUIRE_MFA=true`를 적용합니다.

### 워커와 한계 표시

`unknown` 접수는 자동 재발송하지 않습니다. 모의 공급자는 접수 원장으로 결과를 조정합니다. 실제 공급자는 확인된 결과를 브리지로 반영하거나 담당자가 조사해야 합니다. 웹훅 형식을 임의로 SOLAPI 규격이라고 간주하지 않습니다.

HTTP 설치 검사는 항상 JavaScript 미실행 경고를 남깁니다. 격리 브라우저 검사도 등록 태그 비교가 성공했을 때 전체 사이트 완전 검증으로 표시하지 않고 `partial`로 둡니다. 클릭·로그인 뒤에 실행되는 경로는 고객별 시나리오 확장이 필요합니다.

## 운영 출시 전에 필요한 일

1. 고객 업종·처리 구조에 맞춰 문구, 법적 처리 근거, 보유기간과 통지 내용을 검토합니다.
2. SOLAPI 계정·등록 발신번호·080 계약을 설정하고, 허가된 시험 번호로 결과·거부 지연·접수 취소 범위를 검증합니다. 확인되지 않은 커넥터를 실시간 차단 등급으로 올리지 않습니다.
3. 격리 스캐너 컨테이너를 Linux/Docker에서 실행하고 egress 제한과 Chromium sandbox를 검증합니다.
4. API·워커를 관리 프로세스로 운영하고 HTTPS·비밀 관리·감시·암호화 백업을 설정합니다. 운영 데이터 복원 훈련과 외부 보안 검토를 진행합니다.
5. 결제 사업자의 계정·상품·웹훅 계약을 결정하고 실제 청구·정산을 연결합니다. 현재는 내부 사용량과 발송 한도만 적용합니다.
6. 파일럿 2–3곳에서 고객사 직접 발송 등 우회 경로와 통제 범위를 확인합니다.

SSO·SCIM·다국가 인증·모바일 SDK·다중 공급자·CRM 삭제 자동 실행은 계획서에서도 후속 범위입니다.
